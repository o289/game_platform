# ボードゲームプラットフォーム

## 目的

仲間とボードゲームカフェに行っていたが、そのお店が閉店してしまいゲームができなくなってしまったため、自身でアプリを作り遊べるようにしようと考え作成した

## 概要

ボードゲームカフェで楽しかったゲーム、動画で見た面白そうなゲームをすぐに追加しやすいようにしたプラットフォーム

## 技術

### 言語

TypeScript

### フレームワーク

- React,
- Node.js,
- Express.js,
- tailwindcss: v4系を使用

バージョンの違いによる設定方法の差が大きい場合は明示

---

### socket

**Socket.IO**
このサービスはボードゲーム・カードゲームでの操作・状態管理・ターン管理がメインであり、再接続・復帰処理の方が重要と判断し、IOを採用
思想として、ゲーム以外の設計に時間を掛けたくなかったため、自前実装が必要なwebsocketの採用は見送り

### トンネルサービス

cloudflareトンネル

---

### その他

- ESLint
- Prettier

### 備考

- 基本は"module": "commonjs"を活用。一部必要な場合のみ、"esnext"を使用している

今回は言語をサーバー、クライアントで統一する
また、開発者のPCがスリープ時は遊べなくする予定なのでトンネルサービスはを**cloudflare**採用

## 各ディレクトリの役割

### 非機能

1. core
   ゲーム、ルーム、ソケットなどのプラットフォームに関わるコードやライブラリを配置

2. games
   各ゲームの動作に関するコードを配置。配下にゲーム名ディレクトリを作成

3. app
   実際に動作させる。core, Gamesのゲームの部品を組み合わせる

**coreの機能をgem_nameでも使用できるようにする**

### 機能

1. client
   フロントエンドに関わるものを配置。coreではルーム作成、待機部屋、プレイゲーム選択画面などを配置、GameNameではそのゲームに関するUIを配置

2. server
   サーバーに関わるものを配置。クライアント同様のことをサーバーでも行う

3. shared
   共通で使用する型定義を配置。クライアント同様のことをシェアードでも行う

4. test
   テストに関するものを配置

5. script
   シェルに関するものを配置

6. docs
   ドキュメントの置き場所。ルートにのみ配置しgit ignoreする

7. public assets
   画像や音声データを配置。

## 設計

- ゲーム追加時の変更コストを下げるためにこの構造にした
- **npx create-game [game_name]**で、ゲームのテンプレートを生成できるようにした
- 共通処理の重複を防ぐため、非ゲームロジックをcoreに集約した
